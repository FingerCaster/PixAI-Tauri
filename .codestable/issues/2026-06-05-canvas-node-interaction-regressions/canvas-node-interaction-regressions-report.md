# Canvas 节点交互回归 Issue Report

## 1. 问题现象

本次问题集中出现在 Canvas 工作台的图片节点、文本节点和参考图入口，现象如下：

- 图片节点在通过本地图片添加和历史图加入 Canvas 两条路径下都可复现异常：图片不居中、显示不全，缺少明确删除入口，点击放大预览后的关闭按钮无效。
- 文本节点在输入长内容后，只要鼠标停留在文本输入区内滚动滚轮，内容就会恢复成上一次保存值；如果此前没有保存内容，则会被清空。
- 图片节点语义不清晰：当前看不到明确的连接入口，用户无法判断它是否能作为生成输入使用。
- 工具栏“参考图”按钮展示的是当前会话参考图，但当存在多张参考图时，列表只显示出一张；同时在已有图片节点语义不清的情况下，该入口的职责也显得重复。

## 2. 复现步骤

### 场景 A：图片节点显示 / 预览 / 删除

1. 进入 Canvas 模式。
2. 通过“本地图片”添加图片节点，或从历史图使用“加入 Canvas”创建图片节点。
3. 观察图片节点内的图片显示状态。
4. 点击图片进入大图预览，再尝试点击关闭按钮。

观察到：

- 图片节点内图片不居中，且存在显示不全的情况。
- 节点上没有明确可用的删除入口。
- 大图预览关闭按钮无效，无法正常关闭预览。

### 场景 B：文本节点滚轮导致内容回退

1. 在 Canvas 中创建文本节点。
2. 输入一段较长文本，使文本内容超过节点输入区可见高度。
3. 保持鼠标停在文本输入区内部，滚动鼠标滚轮。

观察到：

- 文本内容回退到上一次保存值。
- 如果此前没有保存内容，文本会被清空。

### 场景 C：图片节点连接入口不可见

1. 在 Canvas 中创建图片节点。
2. 尝试将图片节点作为生成输入使用，观察节点头部和可交互区域。

观察到：

- 当前没有看到明确的连接按钮或连接入口。
- 用户无法确认图片节点是否可以参与后续生成链路。

### 场景 D：参考图按钮列表异常

1. 在当前会话中准备多张参考图。
2. 进入 Canvas 模式。
3. 点击工具栏“参考图”按钮，观察列表内容。

观察到：

- 按钮展示的是当前会话参考图，而不是历史图。
- 当存在多张参考图时，列表只显示出一张。
- 在图片节点职责不清的前提下，该按钮的用途也不明确。

复现频率：稳定。上述问题均可在本地测试窗口中重复观察到。

## 3. 期望 vs 实际

**期望行为**：

- 图片节点中的图片应完整、居中显示，节点具备明确删除入口，图片预览可正常关闭。
- 文本输入区内滚动应只影响输入区滚动，不应改写当前文本内容；长文本应有单独放大编辑入口。
- 图片节点应清晰表达自身是否可作为生成输入使用；如可参与生成，应具备明确可见的连接入口，且文件名或固定尺寸不应遮挡关键操作。
- 如果保留“参考图”按钮，它应稳定列出当前会话的全部参考图；如果图片节点已承载同类职责，则入口职责应保持清晰且不重复。

**实际行为**：

- 图片节点图片显示偏移且不完整，删除入口缺失，预览关闭按钮无效。
- 文本节点在输入区滚轮滚动时会回退或清空内容，也没有放大编辑入口。
- 图片节点当前看不到连接入口，节点用途不明确。
- “参考图”按钮虽然读取的是当前会话参考图，但多图时只显示一张，且与图片节点职责关系混乱。

## 4. 环境信息

- 涉及模块 / 功能：Canvas 工作台；图片节点、文本节点、参考图菜单、图片预览弹窗
- 相关文件 / 函数：待定
- 运行环境：本地开发环境，PixAI Dev（`pnpm dev:client`）
- 其他上下文：问题均在 Canvas 模式下的当前本地测试窗口中发现；用户附带截图显示图片节点存在长标题占位和图片显示不全现象

## 5. 严重程度

**P1** — 这些问题直接影响 Canvas 的基础编辑与使用链路，已超出单纯 UI 瑕疵，但尚未达到整应用完全不可用。

## 备注

- 当前用户倾向于如果图片节点本身最终承担参考图输入职责，则可以考虑移除工具栏“参考图”按钮；该点属于后续分析阶段需要判断的行为边界，不在本报告中定结论。
