# 在 Canvas 里对话式调度节点

## 用户故事

- 作为正在搭建画布链路的创作者，我希望直接说“创建文本节点然后生成”，而不是在 dock、节点和连线之间来回切换。
- 作为已经有多个节点的用户，我希望能用“连接第1个文本到第1个生成”这类指令快速补连线，而不是重新找端口。
- 作为反复改提示词的人，我希望能说“修改最新文本为...”来继续迭代，而不是先在画布里定位节点。
- 作为跑 Canvas workflow 的用户，我希望助手能帮我运行生成节点或整个 workflow，并明确告诉我执行结果或失败原因。

## 为什么需要

Canvas 的强项是把生图流程拆成节点，但节点越多，创建、连接、修改和运行这些小动作越容易打断创作节奏。用户不一定每次都想精确操作画布控件，有些明确动作更适合用一句话交给系统处理。

## 怎么解决

Canvas 右侧提供一个常驻画布助手。用户输入明确的画布操作指令后，助手会把它转换成当前项目内的节点操作，顺序执行，并在对话里返回完成了什么；如果指令不清楚或连接不合法，助手会给出原因和可尝试的示例。

## 边界

- 只服务当前 Canvas project，不跨项目调度。
- 只处理明确的节点、连线、提示词和运行指令，不假装理解开放式聊天。
- 不新增视频、音频或非生图节点能力。
- 不保存助手对话到项目文件里；项目只保存实际节点、连线和视口等画布数据。
