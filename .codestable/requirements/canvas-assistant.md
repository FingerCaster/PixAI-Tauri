# 在 Canvas 里用助手调度节点和生成

## 用户故事

- 作为正在搭建画布链路的创作者，我希望直接说“创建文本节点然后生成”，而不是在 dock、节点和连线之间来回切换。
- 作为已经说不清具体节点编号的用户，我希望助手能先检查当前画布，再选择合适的节点执行操作，而不是要求我精确写出所有参数。
- 作为已经有多个节点的用户，我希望能用“连接第1个文本到第1个生成”这类指令快速补连线，而不是重新找端口。
- 作为在画布里查找节点的人，我希望助手选择或提到某个节点时能自动定位并高亮，让我知道它到底操作的是哪个节点。
- 作为反复改提示词的人，我希望提示词丰富先给出候选并让我确认应用，而不是一上来覆盖原来的文本。
- 作为跑 Canvas workflow 的用户，我希望助手能帮我运行生成节点或整个 workflow，并明确告诉我执行结果或失败原因。
- 作为长期使用同一个 Canvas project 的用户，我希望助手聊天记录能在重启后恢复，并且记录多时能按需加载更早消息。

## 为什么需要

Canvas 的强项是把生图流程拆成节点，但节点越多，创建、连接、检查上下文、修改和运行这些小动作越容易打断创作节奏。用户不一定每次都想精确操作画布控件，也不一定知道当前目标节点的准确名字；更自然的方式是把意图交给助手，让它先看清画布，再调用受控能力完成任务。

## 怎么解决

Canvas 右侧提供一个常驻画布助手。配置 Canvas Agent Provider 后，助手会把当前画布摘要交给支持原生工具调用的模型，由模型选择检查、定位、创建、连接、生成或提出候选变更等受控工具；每次运行会显示过程记录，涉及节点时会定位并短时高亮。提示词丰富这类内容变更先生成待确认候选，用户点应用后才写入节点。未配置 Agent Provider 或 Provider 不支持时，助手仍保留本地规则路径，继续处理明确的节点、连线、提示词和运行指令。助手聊天按 Canvas project 保存在本地会话存储中，打开项目先加载最近消息，记录多时可以加载更早消息，也可以只清空当前项目聊天。

## 边界

- 只服务当前 Canvas project，不跨项目调度。
- V1 只暴露受控 Canvas 工具，不提供删除节点/连接、批量破坏性操作或复杂 workflow 编排。
- V1 只支持原生 tool calling，不做 JSON plan fallback。
- 不新增视频、音频或非生图节点能力。
- 不做长期记忆、跨项目 Agent memory 或云端同步。
- 不保存助手对话到项目文件里；项目只保存实际节点、连线和视口等画布数据。
- 不把助手聊天同步到云端；项目导出默认不包含聊天历史。
